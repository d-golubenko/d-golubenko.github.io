# Персональный академический сайт

Простой сайт для GitHub Pages, без сборки и дополнительных библиотек.
Видимый текст сайта — на английском. Оформление вдохновлено личными страницами
конца 1990-х: спокойный клетчатый фон, объёмные рамки, кнопки и небольшие значки.
Инструкция и комментарии в HTML остаются на русском для удобства редактирования.

## Файлы

- `index.html` — текст страницы и структура разделов.
- `styles.css` — цвета, размеры и адаптация под телефон.
- `publications.html` — полный список из 47 публикаций с DOI, сгруппированных по годам.
- `acid-recovery.html` — извлечение кислоты из модельного выщелачивающего раствора литиевых батарей.
- `selective-ion-transport.html` — селективный перенос одновалентных катионов через PBI-модифицированную мембрану.
- `reverse-electrodialysis.html` — мембраны для получения энергии из градиента солёности.
- `selectivity-measurement.html` — влияние условий измерения на хлорид/сульфатную селективность.
- `pei-brine-mining.html` — алкилированные PEI-мембраны для электродиализа модельного рассола.

Пять исследовательских страниц содержат самостоятельные английские описания, ключевые результаты с интерпретацией, условия экспериментов, ссылки на источники и структурированные данные Schema.org. Исходные рукописи и дополнения в состав сайта не входят.
- `.nojekyll` — отключает обработку Jekyll; файл может быть пустым.
- `README.md` — эта инструкция; не является главной страницей сайта.

## 1. Посмотрите сайт на компьютере

Откройте `index.html` двойным щелчком. Он откроется в браузере.

## 2. Заполните данные

Откройте `index.html` в текстовом редакторе, например Блокноте.
Замените `Your Name` (включая title и подвал; в заголовке это `Your<br>Name`), должность, организацию, биографию,
научные интересы и пример публикации. В контактах замените email дважды:
в `mailto:your.name@example.com` и в видимом тексте.
Сохраните файл в UTF-8 и обновите страницу в браузере.
Не меняйте расширение файла на `.txt`.

Для ссылки на статью используйте:

```html
<a href="https://doi.org/ВАШ_DOI">DOI</a>
```

Для резюме: добавьте настоящий файл `cv.pdf` рядом с `index.html`, затем
добавьте в нужный раздел `<a href="cv.pdf">Резюме (PDF)</a>`.

## 3. Создайте репозиторий на GitHub

Репозиторий — папка проекта на GitHub с историей изменений.

1. Войдите на https://github.com.
2. Нажмите `+` вверху → `New repository`.
3. Введите имя `USERNAME.github.io`, заменив `USERNAME` своим логином GitHub.
   Это логин аккаунта, а не отображаемое имя. Например: `anna-research.github.io`.
4. Выберите `Public`. Загружаемые файлы будут доступны другим людям.
5. Включите `Add README` (или `Add a README file`), чтобы создать начальную ветку.
6. Нажмите `Create repository`.

## 4. Загрузите сайт через браузер

1. На странице репозитория откройте `Code` → `Add file` → `Upload files`.
2. Перетащите все файлы `.html`, `styles.css` и локальный `README.md` в область загрузки.
   Загружайте сами файлы, а не папку, внутри которой они находятся.
3. Если Windows показывает `.nojekyll`, загрузите его также.
   Если не показывает: после загрузки выберите `Add file` → `Create new file`,
   укажите имя `.nojekyll`, добавьте строку `GitHub Pages static site` и сохраните.
   Непустой файл тоже отключает Jekyll.
4. В поле сообщения напишите `Add academic website`.
5. Нажмите `Commit changes` и подтвердите сохранение, если откроется диалог.

Commit — сохранённая версия изменений с коротким описанием.

## 5. Включите GitHub Pages

1. В репозитории откройте `Settings` → `Pages`.
2. В `Build and deployment` → `Source` выберите `Deploy from a branch`.
3. В `Branch` выберите `main`, рядом выберите `/ (root)` и нажмите `Save`.
4. Дождитесь публикации. Она может занять до 10 минут.
5. Откройте `https://USERNAME.github.io/`, подставив свой логин.
   В `Settings` → `Pages` также появится ссылка на сайт.

Инструкция GitHub: https://docs.github.com/en/pages/quickstart

## 6. Обновляйте сайт

На GitHub откройте `index.html` → значок карандаша → измените текст →
`Commit changes`. GitHub Pages автоматически опубликует новую версию.
Можно также изменить локальные файлы и повторно загрузить их через `Upload files`.
При редактировании только на GitHub ваша локальная копия сама не обновится.

Git — инструмент истории версий. GitHub — сервис хранения репозиториев.
GitHub Pages — публикация файлов репозитория в виде сайта.
Для первого сайта устанавливать Git и пользоваться терминалом не требуется.

## Если сайт не открылся

- Проверьте имя репозитория: точно `USERNAME.github.io`.
- Проверьте, что `index.html` лежит в корне и называется именно так.
- Проверьте источник Pages: `main` и `/ (root)`.
- Во вкладке `Actions` посмотрите результат публикации; красный значок означает ошибку.
- Подождите до 10 минут, затем обновите страницу.

Не загружайте пароли, токены и неопубликованные материалы в публичный репозиторий.
